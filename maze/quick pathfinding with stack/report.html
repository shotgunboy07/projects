A Discrete LIFO Automaton with Dual-Mode Rotational Mechanics and Color Diagnostics

1. Executive Summary

This module documents the architectural implementation and verification of a stateful Depth-First Search (DFS) routing engine designed for 2D discrete space navigation. Unlike traditional, globally static graph traversals that evaluate neighbors uniformly, this implementation introduces a localized, directional automaton. The search agent evaluates its spatial frontier based on its immediate historical vector, using two discrete rotational mapping profiles to steer through open corridors and manage collisions with boundary walls.

2. Automaton Kinematics & The Two-Tiered State Machine

The core innovation of this pathfinder is its relative-orientation steering logic. The agent maintains a persistent internal heading state, \(S_{heading} \in \{N, E, S, W\}\), which dictates its initial exploration step upon entering a new coordinate[cite: 5, 6]. When the agent evaluates a transition from its current node, it triggers one of two discrete rotational matrices depending on the environmental feedback (validity check).

2.1 The Open-Field Transition Matrix (rotate_valid)

Ref: maze_DFS.cpp Line 102, test_generator.py Line 11

When the agent steps into an open, unvisited corridor cell (via the next_node_valid function, maze_DFS.cpp line 24), it updates its orientation state by shifting to the opposite vector and rotating 90 degrees counter-clockwise[cite: 7, 8]. This maximizes spatial coverage by pushing the exploration frontier deep into unexplored territory[cite: 8, 9]. We gain the furthest right, upper path possible via this special iteration mechanism[cite: 9].

\[\text{Next Direction} = f_{\text{valid}}(S_{heading})\]

Current Heading (\(S\)) Next Heading (\(S'\)) Vector Shift
East (E) North (N) \((+1, 0) \rightarrow (0, -1)\)
North (N) West (W) \((0, -1) \rightarrow (-1, 0)\)
West (W) South (S) \((-1, 0) \rightarrow (0, +1)\)
South (S) East (E) \((0, +1) \rightarrow (+1, 0)\)

[cite: 10, 11, 12, 13]

2.2 The Collision Recovery Matrix (rotate_invalid)

Ref: maze_DFS.cpp Line 121, test_generator.py Line 12

If the pathfinder detects a wall, a visited cell, or an out-of-bounds boundary (via the next_node_valid function), it triggers a recovery shift. The agent stays inside the current cell but rotates its heading 90 degrees counter-clockwise to seek the next open route.

\[\text{Next Direction} = f_{\text{invalid}}(S_{heading})\]

Current Heading (\(S\)) Next Heading (\(S'\))
East (E) South (S)
North (N) East (E)
West (W) North (N)
South (S) West (W)

[cite: 16, 17, 18]

3. Core Implementation Architecture

The structural framework splits execution between state verification (next_node_valid) and the central stack-driven pathfinding loop.

// Core state transition mapping inside the pathfinder loop
if (s.back().next_node_valid(n, m, maze, s.back(), visited)) {
    node next = s.back();
    if (s.back().path == "N")      { next.y -= 1; next.path = "W"; }
    else if (s.back().path == "S") { next.y += 1; next.path = "E"; }
    else if (s.back().path == "E") { next.x += 1; next.path = "N"; }
    else if (s.back().path == "W") { next.x -= 1; next.path = "S"; }

    s.push_back(next);
    visited.push_back(next);
    continue;
}

Each pass is designed to ensure the agent’s state machine remains consistent with the maze’s topology.

4. High-Fidelity Color Telemetry Diagnostics

To eliminate blind debugging, the executable translates the internal memory states back into a 2D spatial visualization matrix directly within the terminal using ANSI Escape Sequences. Possible paths are highlighted in green while dead ends are marked in red, providing immediate visual feedback on the algorithm’s exploration efficiency.

4.1 Global Target Traversal Reached (Green Channel)

When the destination node \((m-1, n-1)\) is successfully popped, the program isolates the functional path vector from the dead ends and prints the winning coordinates using the \033[1;32m color code.

4.2 Structural Unreachability / Dead Ends (Red Channel)

If the stack exhausts all directional states and collapses entirely, the algorithm retroactively paints every single cell it touched using the \033[1;31m color code. This maps out the entire scope of the dead-end trails, serving as an explicit visual trace of the algorithm’s exploration bounds.

5. Pipeline Verification Infrastructure

To validate the deterministic consistency of the dual-mode state machine, a custom validation pipeline was written in test_generator.py. The test oracle mirrors the state equations exactly, validating the C++ compiled output across a robust suite of 30 test cases, including edge-case open spaces, spiral traps, and high-density random grids.
